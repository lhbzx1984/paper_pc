## 📊 数据模型

### 评审结果模型

```typescript
interface EvaluationResult {
  total_score: number;        // 总分 (0-100)
  grade: string;              // 等级 (优秀/良好/中等/及格/不及格)
  criteria_scores: Array<{    // 各项评分
    name: string;             // 评审项名称
    weight: number;           // 权重
    max_score: number;        // 满分
    score: number;            // 得分
    comment: string;          // 评价
    suggestion: string;       // 建议
  }>;
  overall_comment: string;    // 总体评价
}
```

### 配置模型

```yaml
llm:
  api_key: string           # API密钥
  base_url: string          # API地址
  model: string             # 模型名称
  temperature: float        # 温度参数
  max_tokens: int           # 最大长度

evaluation:
  criteria: Array<{         # 评审标准
    name: string
    weight: float
    max_score: int
    description: string
  }>
  total_score_range: {      # 分数范围
    min: int
    max: int
  }
  grade_levels: Array<{     # 等级标准
    grade: string
    min_score: int
  }>
```

## 🔧 技术选型理由

| 技术 | 选择理由 |
|------|----------|
| FastAPI | 高性能、异步支持、自动文档 |
| React | 组件化、生态丰富、性能好 |
| TypeScript | 类型安全、开发体验好 |
| Ant Design | 企业级、组件丰富、美观 |
| LangChain | RAG支持、LLM集成、易用 |
| ChromaDB | 轻量级、易部署、性能好 |

## 📝 设计原则

1. **单一职责**: 每个组件只负责一个功能
2. **开闭原则**: 对扩展开放，对修改关闭
3. **依赖倒置**: 依赖抽象而非具体实现
4. **接口隔离**: 使用小而专的接口
5. **最少知识**: 组件间低耦合
6. **DRY原则**: 不重复代码
7. **KISS原则**: 保持简单
